# Positioning and ad ideas

Psss is an Apple-native password manager for people who want a simple sign-in and a vault they can keep. Version 1.0 has a specific reason for Strongbox users to try it: Psss can open their existing KeePass vault where it lives, and it stays a KeePass file. For people coming from Apple Passwords, the broader story is being able to keep cards, notes and custom items alongside their logins.

This is a working brief for social ads and product discovery. The [product contract](product.md) defines the promises, and the [roadmap](roadmap.md#two-phases-owner-2026-11-24) defines release scope.

## Demos to develop from the current build

Open with the frustration, show the action that resolves it, and end on visible proof. Use fictional credentials and payment details. The hooks are drafts.

| Audience and hook | What to show | What to verify before publishing |
| --- | --- | --- |
| **Anyone setting up two-factor sign-in.** “Scan this QR code. With what, exactly?” | Start on the iPhone displaying the setup QR. Take a screenshot, choose **Copy and Delete**, and paste it into Psss. A live code appears for that login. The setup key is stored in the encrypted vault, and Psss does not retain the image. | Rehearse the full sequence on a physical iPhone. The flow is built and decoding was checked with generated images. [Verification codes](verification-codes.md) |
| **Strongbox or KeePass users.** “That’s my vault. It’s still my vault.” | Open an existing fictional vault from Files or Finder. Show a card stored as custom fields, map **Valid Thru** to **Expiry** with **Change item type…**, then show the result in **Cards**. The same encrypted file keeps its original fields. End by opening it in another KeePass client. | Validate the chosen fixture and round trip, including the source fields. [KeePass field mapping](items.md#showing-and-mapping-keepass-fields) |
| **Anyone with a replacement card.** “Which Visa is the new one?” | Show two similarly named cards. The last four digits and expiry identify each, with the old one under **Expired**. Open the current card and copy its expiry. | Check the current card view on the device used for filming. The demo uses manual copy at checkout. [Cards](experience.md#cards-tab-approved-2026-11-23-revised-the-same-day) |
| **Anyone cleaning up a vault.** “Wait. Wrong login.” | Delete the wrong login and tap **Undo** to put it back. A second version can show **Recently Deleted** after the Undo banner expires. | Confirm both paths in the filmed build. The immediate Undo is the story here. Apple Passwords also offers 30-day recovery. [Psss items](items.md) · [Apple Passwords recovery](https://support.apple.com/en-us/guide/passwords/mchlee73013a/mac) |
| **Anyone switching apps for a six-digit code.** “The password worked. Now it wants a code.” | Show Safari asking for the code, then choose the suggestion above the keyboard. In a second cut, go to **Codes** and tap the digits to copy them directly from the list. | Reproduce system AutoFill on the signed device used in the ad. It has been demonstrated in the iPhone simulator. [AutoFill](autofill.md) · [Codes](verification-codes.md#copying-a-code-the-codes-view) |

Start with the same-phone QR for the broad audience and the existing-vault demo for Strongbox users. Keep the card, Undo and fast code-copy ideas for short follow-ups.

## Papercuts worth designing around

| Frustration | Proposed flow and the shot that proves it |
| --- | --- |
| **“Did the website change my password, or did only the vault change?”** | Keep a proposed password with the existing login while the change is in progress. After a closed tab, failed submission or interruption, show what is still saved and let the user confirm which password works when the website outcome is unknown. End on one updated login with the previous password still available. The store already reads history and the provider can update a matching login. The recoverable change flow is new. [Psss item history](items.md#built-so-far-2026-11-23) · [1Password’s generated-password recovery](https://support.1password.com/recover-unsaved-password/) |
| **“I have three accounts for this site.”** | Show Personal, Work and School with their account addresses. Carry the selected account from the username screen to the password screen when the system makes that context available. Otherwise, let the person choose explicitly. Film the email-first sign-in where the wrong password usually shows up on page two. [Example from the Bitwarden community](https://community.bitwarden.com/t/multiple-accounts-autofill-chooses-wrong-password/62931) |
| **“This was one login until I changed my password twice.”** | Bring likely duplicates together for review. Show which entry holds a verification code, a note, or a different password. Let the person choose the current password and what else to keep, then make the merge reversible. Film three similar entries becoming one complete login. [Example from the Bitwarden community](https://community.bitwarden.com/t/android-offer-update-existing-login-when-an-app-saves-a-changed-password/103490) |
| **“Was it Apple, Google, or email?”** | Remember the sign-in method with the login. On the next visit, show “You used Sign in with Apple here” where the browser surface supports it. End with the person signing in instead of starting a password reset. [Comparable browser flow in 1Password](https://support.1password.com/explore/whats-new-1password-x/) |
| **“It works on the website. Why can’t I find it in the app?”** | After the person picks a login manually, offer to remember it for that app or an additional verified site where the platform supports it. Show the pairing before saving and let them remove it later. Film the next visit, when the right login appears in suggestions. [Item roadmap](items.md#order-of-work) |
| **“I know I saved it. What did I call it?”** | Find a router by the Wi-Fi network name, a card by its last four, or a login by an old account address. Show the matching detail where it is safe to display. Search already spans the whole vault despite list filters. These extra lookup clues are proposed. [Search rules](experience.md#sort-and-row-lines-owner-2026-11-24) |
| **“I changed two things while offline. Which one survived?”** | In split screen, change one item on Mac and a different one on iPhone while offline. Reconnect and show both changes on both devices. This is a demo for the planned KeePass merge once it is proven, including what happens when both devices change the same field. [Sync roadmap](roadmap.md#two-phases-owner-2026-11-24) |

The interrupted password change is the strongest new concept. Prototype the point of failure first. After a rejected change or a closed tab, the person should be able to find the proposed password, identify the login it belongs to, and choose what to keep. The feature belongs in the existing vault, protected by the same vault credentials.

## Firsthand reports

Collected 2026-11-24 from public user forums and issue trackers. These reports describe specific experiences at the time of posting. Use them to pick scenarios for testing and filming. Frequency and current competitor behavior would need separate verification.

| User report | What to test or explore in Psss |
| --- | --- |
| **The QR code needs a second screen.** One 1Password user on holiday sent a screenshot to their spouse’s phone and scanned it back. Another used an iPad to scan their iPhone, and later said they still needed two devices in their setup. Support pointed to the system’s long-press QR action. [1Password forum, 2022](https://www.1password.community/1password-at-home-31/how-to-scan-on-screen-qr-code-in-ios-app-1594) · [1Password forum, 2025–26](https://www.1password.community/1password-at-home-31/totp-scan-qr-code-is-limited-to-camera-but-i-want-on-screen-22995) | Film the screenshot-to-code path on one iPhone. Test it on a website that shows a QR in an image and one that renders it on the page. End on the live code in the correct login. |
| **The website took the generated password, but the saved login stayed stale.** A Firefox extension user reported having to reset passwords a second time. The generator history held candidates, but finding the right one was work. Another Firefox user confirmed the behavior in the thread, where a later reply pointed to a fix. [Bitwarden forum, 2024](https://community.bitwarden.com/t/problems-with-generating-and-saving-passwords/77003) | Run a password change that succeeds on the site and fails to save in Psss, and one that fails on the site. Check whether someone can recover the new value from the named login and tell which password is current in the vault. |
| **The account was offered, but the email field stayed empty.** A 1Password user authenticated with Face ID on a two-page Google sign-in in Vivaldi and Brave on iOS 17.5.1, then saw no email filled. Their Safari extension filled it. In a separate Keychain thread, users described uncertainty over adding a second account and an unexpected update prompt when entering another person’s login. [1Password forum, 2024](https://www.1password.community/1password-at-home-31/1password-cannot-autofill-google-credentials-13044) · [Apple Support Community, 2022](https://discussions.apple.com/thread/253867944) | Test email-first forms on the supported Safari and system AutoFill surfaces with two accounts. Check both steps and whether the user can tell which account is about to fill. |
| **The fallback picker disappears mid-search.** A Bitwarden user on iOS 18.7.2 reported that long-press AutoFill sometimes closed while they were finding an entry. The issue is closed. [Bitwarden iOS issue, 2025](https://github.com/bitwarden/ios/issues/2138) | Test the manual recovery path on signed devices. If the system picker closes or there’s no inline suggestion, check how quickly a person can find and copy what they need from Psss, then get back to the form. |
| **An account turns into several nearly identical entries.** A KeePassXC user created separate password, code and passkey entries and had to consolidate by hand. A 1Password user reported that two entries for the same site and address with different passkey data were left for manual review. [KeePassXC discussion, 2026](https://github.com/keepassxreboot/keepassxc/discussions/13249) · [1Password forum, 2026](https://www.1password.community/1password-at-home-31/merging-duplicates-23611) | Offer to attach a new sign-in method to the existing login before a duplicate is created. In a cleanup flow, show which methods each entry holds and give the person a way to undo a merge. Treat distinctly registered passkeys as distinct credentials. |
| **The clue is in a field, not the title.** A 1Password Mac beta user found that a last-four card search could show a suggestion that vanished from the full results, depending on how the number was stored. A business user on 1Password’s web app reported being unable to find terms in custom fields and notes. [1Password Mac forum, 2022](https://www.1password.community/1password-at-home-31/trouble-searching-for-credit-card-bank-account-numbers-20052) · [1Password web forum, 2025](https://www.1password.community/1password-at-home-31/full-text-search-doesn-t-work-on-custom-text-fields-22342) | Start with card suffix lookup. The same last four should work whether the stored number has spaces or none, with the match visible as masked digits. Explore opt-in searchable labels for custom items without showing secret values in results. |
| **Copy and AutoFill are unavailable on the device doing the asking.** A Samsung TV owner described entering a generated password with a remote. A separate 1Password user had to count positions for a bank that requests particular characters and described the steps to get to large type. [TV sign-in report, 2023](https://www.reddit.com/r/1Password/comments/10h3wo7/how_do_you_login_to_smart_tv_apps_using_1p/) · [1Password forum, 2022](https://www.1password.community/1password-at-home-31/show-in-large-type-is-missing-in-quick-access-of-1password-8-2217) | Explore **Show in Large Type** as a deliberate reveal, with groups and position markers and a clear way to hide it. Film reading a fictional password from the phone while entering it on another device. Existing large-type features elsewhere make this a convenience demo. |
| **Saved on iPhone still meant another trip into the app.** A Strongbox user reported that an entry saved while browsing on iOS reached other devices only after they opened the main app and vault. Strongbox support described work on initiating a sync from the save flow. [Strongbox user report and support reply](https://www.reddit.com/r/strongbox/comments/1vkg345/syncing_changes_made_inbrowser_via_autofill_on_ios/) | Add a second sync demo to test after the planned merge work. Save a new login from iPhone Safari and use it on the Mac without opening Psss on the iPhone in between. Verify the actual time to availability on a signed build. [Sync roadmap](roadmap.md#two-phases-owner-2026-11-24) |
| **Old logins come back after cleanup.** An iPadOS 16 user reported that old passwords reappeared after individual and batch deletion. Follow-up users described seeing duplicates return after cleanup. The cause is unclear from the thread. [Apple Support Community, 2023–24](https://discussions.apple.com/thread/254842706) | Test deletion against a stale offline vault and a repeat import. When someone deletes an item, check that the stale copy can’t silently return it to the active list or fill suggestions. Keep an explicit restore path. |
| **The same vault opens in both apps, but a sign-in method may not work in both.** A Strongbox user testing an existing KeePassXC vault on iOS 26.5 reported that only one of the tested passkey algorithms was recognized. They reproduced a similar limitation with Apple Passwords and suspected the OS. [Strongbox issue, 2026](https://github.com/strongbox-password-safe/Strongbox/issues/869) | For the existing-vault demo, verify credential types individually. If a passkey is preserved in the file but unusable on that platform, explain the difference during vault review. Keep the ad claim to the round trip demonstrated. |
