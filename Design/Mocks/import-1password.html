Import from 1Password 7

Mock for approval. The importer is built and tested; none of these screens exist. The copy comes from the plan's “Flow and copy”. Where the plan has no words, the sentences are written in the same voice and marked in the decisions. Error and report sentences that come from the importer are used as the code writes them.

What a first-time person must know here.
  • Which thing? One folder made by 1Password 7, named like “1Password Export.1pif”. One vault per export.
  • What do they give? The folder, nothing else. No password, no source picker. If more than one vault of theirs is open in Psss, one extra line names the destination.
  • Where does it go? Into their vault (named on the review screen), encrypted with their vault password. Nothing is uploaded and 1Password is not changed.
  • What can go wrong? The folder is not an export, is empty, is partly unreadable, has no attachments beside it, is too large, was already imported, or the write failed. Each has its own screen below.
  • How do they get out? Cancel on every screen before Import. Nothing is added until Import. Once it starts, it is one write: it finishes or nothing is added.
  • What happens next? A finished screen with Done, and the offer to delete the unprotected export folder.

Where it starts. The Welcome screen's “Import from 1Password” button (today it shows an alert that wrongly names .1pux), a row in Setup, and File, Import from 1Password… on Mac. The first two are drawn below as a Welcome frame; the Setup row has no mock because Setup is not changing otherwise.

Decisions for the owner

  1. The review has one summary line, the destination vault and one filled Import button, with the reasons in a short list under the line.
    Rejected: A separate step for the list (an extra screen the plan wants to avoid). A mapping screen per item (the experience doc rules this out).
    Why: The plan and experience doc ask for “exceptions only”. The list scrolls and the button is pinned, so reading it is optional but reachable.
  2. Changed secrets come first, in a box with a warning mark and their own heading. Not red, not a blocking dialog.
    Rejected: Red text (red is reserved for deletion). A confirmation before Import that lists them (a second modal for something the person cannot fix in Psss). A second Import button labelled “Import Anyway” (more friction than the facts justify; the original is still in 1Password).
    Why: A changed password is the one thing that can lock someone out later, so it must not look like the other lines. The box repeats on the Done screen so the warning is still visible before the export is deleted.
  3. The importer's sentence for a changed secret ends with “Check it in 1Password before you rely on it.” The mock says this once, in the box's intro, and trims it from each line.
    Rejected: Keep the full sentence on every line (repeats the same advice).
    Why: Wording suggestion for the importer's strings; needs the code strings trimmed when a heading says it.
  4. Look-alike logins and the other long groups are collapsed behind one labeled Show.
    Rejected: Expand everything (a long page before the button).
    Why: Progressive disclosure for detail, not for the main job.
  5. The one help line under Import says “Nothing is added until you choose Import.” Progress replaces it.
    Rejected: A line on every screen.
    Why: Help text lives in one place.
  6. There is no Cancel while importing.
    Rejected: A Cancel that rolls back (the write is one commit, so there is nothing to roll back before it, and no way to interrupt it).
    Why: Being honest: cancelling is possible only before Import.
  7. The Done screen offers “Delete Export Folder…” as a bordered button next to a filled Done.
    Rejected: Delete the export automatically (the plan says never). Prominent Delete (it moves the user to a destructive step on the way out). No offer (an unencrypted copy of every password stays on disk).
    Why: The plan. It is bordered because the Mac action only moves the folder to the Trash.
  8. On iPhone and iPad the delete confirmation does not say “Trash”.
    Rejected: Copy the Mac wording.
    Why: I could not confirm what happens to a folder deleted from a file provider on iOS.
  9. Second import: “Import These Too” is offered for items the person deleted in Psss.
    Rejected: Never offer (the plan's flag exists for a reason, and a deleted item is gone for good after 30 days). Restore from Recently Deleted instead (works only while the item is still there).
    Why: One way back that works whether or not the item is still in Recently Deleted. The importer's own sentence, “Restore it there if you want it back.”, then contradicts this button and should change to “Import These Too”, or the button should be offered only for items that are gone for good.
  10. Errors use a warning mark and ordinary text, with one or two labeled buttons.
    Rejected: Red error text, as the lock screen uses today. An alert for each (the person loses the explanation when it closes).
    Why: Red is for deletion; an alert cannot be read twice.
  11. The entry point is one labeled button on Welcome, a Setup row and File, Import from 1Password…, with no picker for the source.
    Rejected: A source picker (the plan detects the source).
    Why: Fewer choices.

Conflicts with Apple's guidance

  1. A warning glyph in system orange on a sheet.
    The HIG allows system colours with semantic meaning, and this one is neither the accent nor the deletion red. If the owner wants no colour except the accent, the box keeps its heading and border and drops the glyph colour.
  2. A full-width pinned action area on a sheet.
    On iOS the HIG places sheet actions in the navigation bar (Cancel at left, the action at right). The mock keeps the one primary action at the bottom, labeled, as the project rules ask, and Cancel at left. The trade-off is that the action is further from the top, and it does not match system sheets such as Mail's.
  3. Progress with no Cancel.
    The HIG says to let people cancel long operations. This one is a single write of a few seconds that cannot be interrupted safely.
